# 验收、复现与公开证据

## 三层完成标准

1. **合同通过**：模型存在、参数合法、输入顺序正确，未知字段未被忽略。
2. **执行通过**：任务成功、结果及时下载、全文件可解码、尺寸/帧数/音轨符合记录。
3. **内容通过**：真实动作、形体、身份、选区、光照、接缝、口型达到该项目要求。前两层不证明第三层。

视频：

```bash
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,nb_frames:format=duration -of json shot.mp4
ffmpeg -v error -i shot.mp4 -f null -
```

看全画幅与动作峰值；接缝±0.5秒；高清看最快运动帧；RIFE后看新增插值帧，不仅看原帧。听完整音轨；不要发布未听过的模型原生语音。

图像：解码数量等于请求n，RGB/RGBA模式、尺寸、alpha，脸/手/文字/物体边缘；严格局部编辑验证mask外逐像素不变。检测器漏检应标记unknown，不能算通过。

## 每条候选记录

`request.json`、有序input文件哈希、model/profile/LoRA及强度、seed（若支持）、job ID、提交与完成时间、原始结果、处理版本、人工选择理由。队列/传输/推理耗时分别记录；共享主机的历史速度不当作服务SLA。

建议目录：`runs/<project>/<shot>/<take>/`，结果文件与request同存；输出过期前先下载。任何“质量改善”结论写清样本数、模式、尺寸、是否同seed、是否同一输入；单次smoke只证明该请求可跑。

## 本地总库与公开版

本地保留全部原始记录。公开版只迁移通用流程、规范字段、已清理示例和可复现工具；不公开肖像训练数据、私人触发词、内部拓扑、凭证、原始聊天、下载目录、非公开媒体及其哈希。模型目录只摘录明确要讲的公共适配器。

更新顺序：读当前schema→更新对应配方→最小测试→更新验证记录和INDEX→扫描导出目录→从干净历史发布。不要将总库history直接subtree推成公开repo。外部勘误先审并回流本地总库，再导出下一版。
